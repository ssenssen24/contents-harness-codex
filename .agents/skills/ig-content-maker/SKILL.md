# 인스타그램 콘텐츠 기획·제작

AGENTS.md, brand.md, content-design.md, 실행의 research.md·sources.json·state.json을 읽는다. [산출물 계약](../../../scripts/contract.md)에 따라 승인·카드 ID·산출물을 연결한다. 브랜드 기준을 중복 정의하지 않는다.

## 기획과 승인
1. research 검사를 통과했는지 확인하고 조사 한계를 반영한다. 주제가 없다면 후보를 제안하고 선택을 받는다.
2. plan.md는 사람이 검토하는 기획서다. 기획 요약 → 카드별 구성표(순서·역할·실제 문구·화면 구성·사진·CTA·출처) → 사진 제작 방향 → 캡션 → 확인 사항 → 문서 하단 `content-plan` JSON 블록 하나 순서로 작성한다. 확인값·제안·미확인을 구분하며 별도 기획 JSON은 만들지 않는다. `scripts/plan_document.py`의 compose()로 검토 영역을 생성하고 새 실행 state.json에는 `plan_document_format: human-first-v1`을 기록한다. 문구 수정은 하단 데이터에 반영한 뒤 `python3 scripts/plan_document.py PLAN_PATH --sync`로 표·사진 방향·캡션을 함께 갱신한다. 불일치를 수동으로 무시하지 않는다.
3. 신규 사진의 스타일은 brand.md·content-design.md가 우선이다. plan.md는 그 안에서 새로운 장면을 정한다. 제안값 조정 시 이유를 적는다.
4. plan 검사 후 **기획서 파일 링크와 카드별 구성표를 답변에 함께** 제시한다. 답변 표에도 현재 기획의 실제 문구와 화면 구성을 표시하며 하단 JSON만 보여주고 승인을 요청하지 않는다. 검토 포인트를 제시하고 `--digest plan`으로 고정한다. **명시적 사용자 기획 승인 전 사진을 생성하지 않는다.** 승인 원문·시각·digest를 state.json에 적는다.

## 사진·HTML과 승인
1. 기획 승인이 현재 digest에 유효한지 확인한다. 설치된 imagegen 스킬을 읽고 Codex 이미지 도구로 신규 사진을 만든다. 다른 기획 사진은 재사용하지 않는다. 미사용·실패를 생성 완료로 기록하지 않는다.
2. 텍스트·로고 없는 사진을 preview/images에 저장한다. assets.json에 실제 생성 시각·도구·프롬프트·실행 ID·해시를 기록한다. 로고·장식은 assets/reference를 참조한다.
3. HTML에 카드별 `data-card-id`, `data-width`, `data-height`, 문구별 `data-copy` 요소를 둔다. 사진·로고·도형·텍스트를 별도 요소로 구성한다. 전체 카드 목록과 확대 검토가 가능하게 한다.
4. 설치된 브라우저 스킬을 읽고 로컬 HTML을 실제로 연다. 렌더 치수·순서·문구·이미지·서체 로딩·글자 넘침을 읽어 browser-check.json에 기록하고 screenshots에 화면을 저장한다. 계획값을 복사해 렌더 증거로 삼지 않는다.
5. preview 검사 후 HTML과 화면을 제시하고 `--digest preview`로 고정한다. **명시적 프리뷰 승인 전 Figma에 쓰지 않는다.** 승인 원문·시각·digest를 기록한다.

## Figma·최종 전달
1. 두 승인의 유효성을 확인한다. 설치된 Figma 스킬을 도구별 요구에 맞게 읽는다. 실행별 새 파일을 만들며 재개 시 기록된 결과 파일을 이어 쓴다. 원본 파일에 쓰지 않는다.
2. 승인된 문구·순서·사진·구성을 옮긴다. 텍스트는 TEXT, 도형·장식은 벡터/도형, 사진은 별도 이미지 레이어로 유지한다. HTML 캡처나 한 장짜리 카드 이미지로 제작 완료 처리하지 않는다.
3. 실제 Figma를 다시 읽어 카드 노드 ID·치수·순서·텍스트 노드의 문구·이미지와 벡터 노드를 figma.json에 기록한다. 실제 읽은 속성과 읽은 시각을 남긴다. 카드 스크린샷을 승인된 HTML과 대조한다.
4. 카드별 PNG를 final/png에 내보내고 승인 기획의 캡션을 caption.md에 저장한다. Figma·PNG 시각 검토 결과는 checks/review.md에 기록한다.
5. final 검사 후 전체 산출물·Figma 링크·검사·출처를 전달한다. 게시·예약 발행은 하지 않는다. 미실행·미완료 부분을 명시한다.

## 수정·복구
- 문구·사진·구성 변경 시 해당 단계부터 재승인한다. 화면 차이 없는 경로 변경은 내용 해시가 동일한지 검사한다.
- 필요한 수정본만 단계별 v002 폴더에 보존하고 state.paths를 갱신한다. 새 digest를 과거 승인에 덮어써 승인된 것으로 만들지 않는다.
- 도구 실패는 blocked로 기록하고 원인·마지막 성공 단계·다음 조치를 남긴다. 오류 수정 후 한 번 재시도해 같은 장애면 사용자에게 알린다.
- 자동 통과로 사용자의 메시지·시각 승인을 대신하지 않는다.
